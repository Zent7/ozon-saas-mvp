# Резервное копирование и восстановление

Этот проект уже содержит локальный production-like контур резервного копирования для Windows:

- ежедневный backup PostgreSQL;
- backup сгенерированных документов из runtime-каталога;
- хранение последних backup-наборов;
- логирование выполнения;
- восстановление базы и документов из одного backup-набора.

## Что защищается

Backup-контур должен покрывать:

- клиентов;
- обращения;
- бланки и их номера;
- журналы документов;
- сгенерированные документы и связанные рабочие файлы из runtime-каталога.

Важно:

- `assets/templates/` содержит поставляемые шаблоны и не является рабочим runtime-хранилищем;
- обязательному backup подлежит именно каталог `GENERATED_DOCUMENTS_DIR`;
- по умолчанию это `storage/generated`, если переменная окружения не переопределена.

## Структура backup-набора

Каждый запуск `backup-db.ps1` создаёт папку вида:

```text
backups/medcenters_YYYYMMDD_HHMMSS/
```

Внутри:

- `database.sql` - SQL-дамп PostgreSQL;
- `documents.zip` - архив runtime-документов, если включён `ArchiveDocuments`;
- `manifest.json` - состав backup-набора;
- `summary.json` - краткий итог выполнения.

Отдельный лог пишется в `logs/backups/backup_YYYYMMDD_HHMMSS.log`.

## Ручной запуск backup

Из корня проекта:

```powershell
.\backup-db.ps1
```

Полезный пример с явными параметрами:

```powershell
.\backup-db.ps1 `
  -OutputDir .\backups `
  -LogDir .\logs\backups `
  -DocumentsDir .\storage\generated `
  -KeepLast 30 `
  -ArchiveDocuments $true
```

Поддерживаемые основные параметры:

- `OutputDir` - куда сохранять backup-наборы;
- `LogDir` - куда сохранять логи;
- `DocumentsDir` - runtime-каталог документов;
- `ArchiveDocuments` - включать ли архив документов;
- `KeepLast` - сколько последних backup-наборов хранить;
- `RetentionDays` - дополнительное удаление backup-наборов старше N дней.

## Как проверить, что backup прошёл

После запуска проверить:

1. В `backups/` появилась новая папка `medcenters_...`.
2. Внутри лежит `database.sql`.
3. Если включён backup документов, внутри лежит `documents.zip`.
4. В `logs/backups/` появился лог с тем же timestamp.
5. В логе есть строки `Backup completed successfully.` без `ERROR`.

## Восстановление

### 1. Проверка backup-набора без восстановления

```powershell
.\restore-db.ps1 `
  -BackupPath .\backups\medcenters_20260512_020000 `
  -Mode full `
  -ValidateOnly
```

### 2. Восстановить только базу

```powershell
.\restore-db.ps1 `
  -BackupPath .\backups\medcenters_20260512_020000 `
  -Mode db `
  -DropExisting
```

### 3. Восстановить только документы

```powershell
.\restore-db.ps1 `
  -BackupPath .\backups\medcenters_20260512_020000 `
  -Mode documents `
  -ReplaceDocuments
```

### 4. Восстановить полный backup-набор

```powershell
.\restore-db.ps1 `
  -BackupPath .\backups\medcenters_20260512_020000 `
  -Mode full `
  -DropExisting `
  -ReplaceDocuments
```

Поддерживаемые режимы:

- `db` - только PostgreSQL;
- `documents` - только runtime-документы;
- `full` - база и документы вместе.

Флаги:

- `DropExisting` - удалить текущую схему PostgreSQL перед restore;
- `ReplaceDocuments` - заменить текущий каталог документов содержимым из backup;
- `ValidateOnly` - только проверить входные файлы, ничего не восстанавливая.

## Ежедневный автоматический запуск в Windows

Для регистрации задания планировщика:

```powershell
.\register-backup-task.ps1 `
  -TaskName "MedCenters Daily Backup" `
  -StartTime "02:00" `
  -KeepLast 30 `
  -DocumentsDir .\storage\generated
```

Скрипт зарегистрирует ежедневный запуск `backup-db.ps1` через Windows Task Scheduler.

Проверка:

1. Открыть `Task Scheduler`.
2. Найти задачу `MedCenters Daily Backup`.
3. Запустить её вручную через `Run`.
4. Убедиться, что появился новый backup-набор и свежий лог.

## Минимальные эксплуатационные правила

- Хранить минимум 30 ежедневных backup-наборов.
- Не хранить backup только внутри volatile-временных папок.
- Регулярно проверять не только создание backup, но и реальное восстановление на тестовом окружении.
- После крупных изменений в генерации документов проверять, что runtime-каталог документов всё ещё входит в backup-контур.
- Следить за свободным местом на диске: место нужно под PostgreSQL dump, архив документов и 30 последних наборов.
