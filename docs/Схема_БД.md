# Предварительная схема базы данных

## Общий подход
- PostgreSQL как основная БД.
- Все таблицы содержат `id`, `created_at`, `updated_at`.
- Для критичных сущностей добавляется `deleted_at` для логического удаления.
- Данные двух центров хранятся в одной базе, но операционные записи привязываются к центру.

## Связи
- один `center` -> много `users`
- один `client` -> много `client_documents`
- один `client` -> много `encounters`
- один `encounter` -> много `encounter_services`
- один `encounter` -> много `payments`
- одна `service_category` -> много `services`
- один `template` -> много фактов генерации

## Правила антидублей
При создании клиента проверять:
- совпадение по ФИО + дате рождения
- совпадение по номеру телефона
- совпадение по документу
- совпадение по СНИЛС при наличии

На первом этапе лучше использовать:
- предупреждение о возможном дубле
- ручное подтверждение оператором

## Что мигрируем из старой базы в первую очередь

- услуги

- документы клиента при наличии
