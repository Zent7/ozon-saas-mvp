# Архитектура проекта

## Рекомендуемый стек

### Backend
- Python 3.12+
- FastAPI
- SQLAlchemy 2.x
- Alembic
- Pydantic 2
- PostgreSQL
- JWT или cookie-based session для авторизации
- `python-docx` / шаблонизатор документов на втором этапе
- `lxml` или аналог для XML-выгрузок

### Frontend
- React
- TypeScript
- Vite
- React Router
- TanStack Query
- React Hook Form
- Zod
- Tailwind CSS или CSS Modules

### Инфраструктура
- Docker Compose для локальной среды
- PostgreSQL как основная БД
- Файловое хранилище для временной генерации документов/XML
- Планировщик для резервных копий и фоновых задач

## Почему именно такой стек
- FastAPI быстро позволяет собрать надежный CRUD и API для сложной формы регистрации.
- PostgreSQL хорошо подходит под поиск, связи, аудит и миграции.
- React + TypeScript дают удобный интерфейс для операторской работы с быстрыми сценариями.
- SQLAlchemy и Alembic позволяют безопасно вести структуру БД по мере роста проекта.

## Архитектурные принципы
- Одна база данных для двух центров.
- Центр хранится как отдельная сущность и пробрасывается в операционные записи.
- Клиент единый на оба центра, но обращения, документы и операции привязаны к центру.
- Удаления для критичных данных по умолчанию логические.
- Все действия пользователя, влияющие на данные, фиксируются в аудите.

## Основные модули backend

### `app/core`
- настройки приложения
- безопасность
- конфигурация окружения

### `app/db`
- подключение к БД
- базовый класс моделей

### `app/models`
- SQLAlchemy-модели

### `app/schemas`
- Pydantic-схемы запросов и ответов

### `app/api`
- роутеры по доменам:
  - auth
  - clients
  - encounters
  - services
  - documents
  - recalls
  - users

### `app/services`
- бизнес-логика
- проверка дублей
- генерация документов
- генерация XML
- нумерация бланков

## Рекомендуемые этапы технической реализации
1. Поднять БД и миграции.
2. Реализовать авторизацию и справочники.
3. Реализовать клиентов и защиту от дублей.
4. Реализовать обращения и услуги.
5. Реализовать документы и нумерацию.
6. Реализовать повторы, аудит, бэкапы и импорт.

## Нефункциональные ориентиры
- отклик поиска по клиентам до 1 секунды на рабочем объеме
- аудит изменения критичных данных
- возможность ежедневных резервных копий
- миграции БД без ручной правки схемы
