# Техническое задание

## Название проекта
Веб-система учета клиентов, обращений и документов для двух медицинских центров.

## Цель проекта
Разработать единую браузерную систему, которая заменит текущую локальную/файловую схему работы, объединит данные двух центров в одной базе и сократит количество ручных действий сотрудников при оформлении клиентов, обращений и документов.

## Формат работы системы
- Веб-приложение, доступное через браузер.
- Единая база данных для двух медицинских центров.
- Одновременная работа до 20 сотрудников.
- Разграничение доступа по учетным записям.

## Основные бизнес-задачи
- Вести единую базу клиентов по двум центрам.
- Быстро находить клиента и видеть его историю.
- Создавать обращение сразу после создания клиента без лишних шагов.
- Подтягивать услуги, оплату и комментарии в рамках обращения.
- Формировать документы по шаблонам без ручного переписывания данных.
- Контролировать повторные обращения по срокам.
- Сохранять данные безопасно и с резервным копированием.

## Роли пользователей
Минимально на первом этапе:
- Администратор
- Регистратор
- Пользователь центра

На будущее:
- Гибкая ролевая модель с настройкой прав на просмотр, создание, редактирование, удаление, выгрузку документов и управление справочниками.

## Функциональные требования

### 1. Авторизация и пользователи
- Вход по логину и паролю.
- Хранение пользователей в системе.
- Фиксация автора создания записи.
- Возможность блокировки пользователя.
- Журнал входов в систему.

### 2. Работа с двумя центрами
- Ведение данных двух центров в одной базе.
- Привязка клиента, обращения и документов к центру.
- Фильтрация списков по центру.
- Возможность видеть общую базу клиентов при сохранении разделения рабочих потоков по центрам.

### 3. Клиенты
- Единая карточка клиента.
- Хранение ФИО, даты рождения, пола, телефона, документов, адреса и дополнительных полей.
- Поиск по:
  - ФИО
  - дате рождения
  - телефону
  - номеру документа
  - СНИЛС / полису / другим идентификаторам при наличии
- Защита от дублей при создании.
- Предпросмотр клиента в списке без открытия полной карточки.
- История всех обращений клиента.

### 4. Обращения
- Создание обращения сразу после добавления нового клиента.
- Создание обращения из карточки существующего клиента.
- Исключение повторного выбора клиента при переходе в обращение.
- Хранение даты обращения, центра, типа оплаты, суммы, комментариев, автора записи.
- Привязка нескольких услуг к одному обращению.
- История обращений клиента в хронологическом порядке.

### 5. Услуги
- Справочник услуг.
- Категории услуг.
- Цена услуги.
- Добавление одной или нескольких услуг в обращение.
- Возможность менять состав и стоимость услуг в рамках обращения с учетом прав пользователя.

### 6. Документы и шаблоны
- Подключение шаблонов документов, используемых в текущей работе.
- Плановый объем: около 20 шаблонов, фактически в текущей базе обнаружено 48 записей шаблонов, потребуется уточнение рабочих.
- Автоматическая подстановка данных клиента, обращения, услуг, центра и сотрудника в шаблон.
- Формирование документа на скачивание без обязательного хранения файла в системе.
- Генерация XML-файлов по утвержденному шаблону.
- Сохранение XML в указанную папку для дальнейшей загрузки в реестр.

### 7. Повторные обращения
- Хранение даты следующего рекомендуемого обращения.
- Правило срока повтора по типу услуги или документу.
- Отдельный раздел "Ближайшие повторы".
- Отображение:
  - приближающихся повторов
  - просроченных повторов
- Фильтрация по центру и периоду.

### 8. Импорт данных
- Загрузка стартовой базы из существующих источников.
- Основной источник для анализа миграции: текущая база Access (`.mdb`).
- Дополнительный источник: Excel (`Водитель 2.0.xls`) при необходимости.
- Перенос клиентов, обращений, услуг, пользователей, шаблонов и связанных сущностей.
- Обработка дублей и нормализация данных в рамках миграции.

### 9. Удаление и контроль действий
- Мягкое удаление или архивирование критичных данных.
- Уведомление на email при удалении записи.
- Журнал действий пользователей:
  - создание
  - изменение
  - удаление
  - вход в систему
  - выгрузка документов

### 10. Автонумерация
- Автоматическая нумерация бланков для определенных услуг.
- Настраиваемые счетчики по типу документа/услуги.
- Исключение ручных конфликтов по номеру.

### 11. Производительность и удобство
- Быстрый поиск по клиентской базе.
- Минимум переходов между экранами.
- Быстрое создание обращения из поиска.
- Отображение ключевой информации в таблице без открытия карточки.
- Адаптация интерфейса под рабочий процесс регистратора.

### 12. Резервное копирование
- Автоматическое резервное копирование базы данных.
- Хранение резервных копий по расписанию.
- Возможность восстановления из резервной копии.
- Логирование выполнения резервного копирования.

## Нефункциональные требования
- Работа в современных браузерах.
- Поддержка не менее 20 одновременных пользователей.
- Защита паролей в хэшированном виде.
- Разграничение прав доступа.
- Базовая защита от случайной потери данных.
- Возможность последующего расширения функционала.

## Открытые вопросы перед стартом
- Какие из 48 шаблонов реально используются ежедневно.
- Нужны ли разные права по двум центрам.
- Нужна ли печать напрямую из браузера или достаточно скачивания файлов.
- Какие именно XML-шаблоны обязательны на первой версии.
- Какие удаления допустимы физически, а какие только логически.
- По каким услугам должна работать автонумерация.
- Нужно ли хранить историю изменений полей клиента и обращения.

- клиентов
- обращения
- услуги
- поиск
- импорт базы
- 5-10 самых важных шаблонов
