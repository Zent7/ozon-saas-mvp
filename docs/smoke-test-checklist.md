# Smoke-test перед прогоном

Этот чеклист нужен для ручного прохода рабочего места оператора перед показом или перед тем, как отдавать архив другу на прогоны.

## 1. Запуск

| Статус | Проверка | Что сделать | Ожидаемый результат | Комментарий |
| --- | --- | --- | --- | --- |
| [ ] | Docker-база | `docker compose -p medcenters up -d db` | Контейнер `medcenters_db` запущен, порт наружу `5434` | На Windows локальный PostgreSQL может занимать `5432`, поэтому проект использует `5434` |
| [ ] | Backend | Запустить `start-demo.ps1` или вручную `uvicorn app.main:app --reload --port 8000` | `http://127.0.0.1:8000/api/v1/health` отвечает | Если падает при старте, первым смотреть миграции и seed |
| [ ] | Frontend | Открыть `http://localhost:5173/` | Открылась демка рабочего места | `start-demo.ps1` запускает Vite на фиксированном `5173` |
| [ ] | Чистый браузер | Открыть демку в инкогнито или очистить localStorage | Нет старых тестовых данных в форме нового клиента | Особенно важно после проверки старой демки |

## 2. Оператор: клиент

| Статус | Проверка | Что сделать | Ожидаемый результат | Комментарий |
| --- | --- | --- | --- | --- |
| [ ] | Поиск клиента | Ввести фамилию/телефон/дату рождения существующего клиента | Список фильтруется без зависаний | Проверить русские буквы и частичный ввод |
| [ ] | Выбор клиента | Нажать на найденного клиента | Карточка клиента открылась, услуги доступны | Не должно сбрасывать выбранную строку |
| [ ] | Новый клиент | Открыть "Новый клиент" | Поля пустые, без подставленных тестовых паспорта/телефона/адреса | Это уже исправлялось, проверить руками |
| [ ] | Создание клиента | Заполнить минимум обязательных полей и нажать ОК | Клиент появился в списке, номер не `999999` | Номер должен идти из backend/SQL, без фиктивного значения |
| [ ] | Обновление страницы | Нажать F5 после создания | Созданный клиент остался в базе и находится поиском | Проверяет реальное сохранение, а не только экран |

## 3. Услуги и обращение

| Статус | Проверка | Что сделать | Ожидаемый результат | Комментарий |
| --- | --- | --- | --- | --- |
| [ ] | Категории услуг | Переключить "Все", "ВУ", "ГИМС", "Медкнижка", "Справки", "УЗИ", "ЭКГ" | Категории показывают релевантные услуги или честно пустой список | Пустая категория должна быть понятной, без ошибки |
| [ ] | Добавление услуги | Выбрать 1-2 услуги | Услуги попали в текущее обращение | Проверить цену, количество, статус |
| [ ] | Смена клиента | Выбрать другого клиента | Услуги прошлого клиента не смешались с новым | Важная проверка изоляции состояния |
| [ ] | Обновление страницы | Создать обращение, обновить страницу | Обращение и услуги восстановились из backend | Проверяет persistence |

## 5. Документы

| Статус | Проверка | Что сделать | Ожидаемый результат | Комментарий |
| --- | --- | --- | --- | --- |
| [ ] | Генерация DOCX | Сформировать документы по выбранной услуге | Файл скачивается, открывается в Word | Проверить переносы, подписи, пустые строки |
| [ ] | Генерация XML | Сформировать XML, если услуга его требует | XML скачивается и содержит данные клиента | Особенно водительские/ЧОД/тракторные |
| [ ] | Неверный шаблон | Нажать услугу, где шаблон не задан | Пользователь видит понятное сообщение | Такие места вынесены в `ui-noop-audit.md` |
| [ ] | Повторная генерация | Сформировать документ второй раз после изменения данных | Документ обновился, старые данные не остались | Проверить дату/ФИО/паспорт |

## 6. Ошибки, которые обязательно записывать

Для каждого бага заполнить `docs/bug-report-template.md`:

- что нажали;
- какой клиент/услуга/врач;
- что ожидали;
- что произошло;
- скриншот;
- текст ошибки из backend/браузера, если есть.
