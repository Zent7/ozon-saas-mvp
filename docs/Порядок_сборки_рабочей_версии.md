# Порядок сборки рабочей версии

## Цель

Собираем не сайт с разделами, а рабочее место оператора:

1. открыл;
2. ввел данные или нашел клиента;
3. выбрал услуги;
4. оформил обращение;
5. сформировал документы;
6. перешел к следующему клиенту.

## Этапы

1. Клиенты и быстрый поиск.
2. Услуги.
3. Обращения.
4. Документы.
5. XML.
6. Бланки и автонумерация.
7. Пользователи и права.
8. Удаления, аудит и email-уведомления.
9. Повторы.
10. Импорт старой базы.

## Первый боевой модуль

Модуль `Клиенты` должен быть фундаментом для всего остального:

1. простой номер пациента `1, 2, 3...`;
2. быстрый backend-поиск с лимитом выдачи;
3. поиск по номеру, ФИО, телефону, СНИЛС и полису;
4. антидубли только по жестким признакам: телефон, СНИЛС, полис;
5. frontend debounce 250 мс, чтобы не дергать backend на каждую клавишу;
6. не загружать всю базу сразу.

## Требования к скорости

Для стабильной работы на 100 000 клиентов закладываем сразу:

1. PostgreSQL в рабочей версии;
2. индексы на поля поиска;
3. лимит выдачи по умолчанию 50 записей;
4. поиск через backend, а не фильтрацию всех клиентов в браузере;
5. debounce 200-300 мс;
6. виртуализацию таблицы на frontend, когда появятся большие списки;
7. отдельную генерацию документов, не связанную с поиском клиентов.
