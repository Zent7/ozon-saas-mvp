# Карта полей шаблонов

Ниже зафиксирована стартовая карта полей для шаблонов, которые уже можно брать в первую рабочую очередь.

## Поддерживаемые типы подстановки
- текстовые токены внутри шаблона, например `[ClientCalc]`
- токены в формате `[ | ClientCalc | ]`
- Word bookmarks, например `BirthDateCalc_DAY`, `VisitDate_YEAR`, `SubjectCalc`

## Источники данных

### Данные клиента
- ФИО клиента
- дата рождения
- телефон
- СНИЛС
- адрес / текст адреса

### Данные обращения
- номер обращения
- дата обращения
- центр
- сумма
- тип оплаты

## Реализованные поля контекста
- `ClientCalc` -> ФИО клиента
- `ReferenceNumber` -> номер обращения или ID клиента
- `BirthDateCalc` -> дата рождения целиком
- `BirthDateCalc_DAY` -> день рождения
- `MonthBirthDateCalc` -> месяц рождения
- `BirthDateCalc_YEAR` -> год рождения
- `VisitDate_DAY` -> день обращения
- `MonthCalc` -> месяц обращения
- `VisitDate_YEAR` -> год обращения
- `SubjectCalc` -> текст адреса клиента
- `SubjectCalc1` -> текст адреса клиента
- `Therapist` -> значение врача/специалиста
- `Ophthalmolog` -> значение врача/специалиста
- `Neurolog` -> значение врача/специалиста
- `Otolaryngolog` -> значение врача/специалиста
- `InstrumentalExamination` -> текст результата исследования
- `LaboratoryStudy` -> текст результата лаборатории

## Шаблон `BодительскаяСправка_шаблон.docx`
Выявленные поля:
- `Therapist`
- `Ophthalmolog`
- `Neurolog`
- `Otolaryngolog`
- `InstrumentalExamination`
- `LaboratoryStudy`

Логика:
- врачебные поля берутся из блока осмотра/заключения
- исследования и лаборатория берутся из результатов обращения

## Шаблон `082у_шаблон.docx`
Выявленные bookmarks:
- `BirthDateCalc_DAY`
- `MonthBirthDateCalc`
- `BirthDateCalc_YEAR`
- `VisitDate_DAY`
- `MonthCalc`
- `VisitDate_YEAR`
- `SubjectCalc`
- `CityCalc`
- `StreetCalc`
- `HouseNumberCalc`
- `ApartmentNumberCalc`

Логика:

- адресные bookmarks сейчас заполняются из общего текстового адреса и могут быть детализированы позже
- категории пока оставлены как пустые значения до уточнения бизнес-логики

## XML-шаблоны
На первом этапе поддерживается замена:
- `[FieldName]`
- `[ | FieldName | ]`
- `{{FieldName}}`

Это позволяет перейти к реальной выгрузке XML после уточнения состава обязательных полей в каждом формате.

## Следующий шаг по шаблонам
- зафиксировать 5-10 обязательных шаблонов первой очереди
- для каждого шаблона составить полную карту полей
- выделить поля, которые должны идти из клиента, обращения, услуги, центра и пользователя
